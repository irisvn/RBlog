Kết nối frontend Nuxt hoặc Next với RBlog

RBlog là trang quản trị và là nguồn nội dung. Trang công khai là một app Nuxt hoặc Next riêng, đọc nội dung qua Content API chỉ đọc từ phía server, và được RBlog báo qua webhook mỗi khi nội dung thay đổi để làm mới cache. Tài liệu này đi từ lúc lấy key tới lúc chạy thật, kèm code mẫu cho cả hai framework.

01Kiến trúc

  • Chỉ đọc, chỉ nội dung đã đăng. API không bao giờ trả bản nháp, bài hẹn giờ chưa tới giờ hay bài trong thùng rác, kể cả khi hỏi bằng slug cũ. Bản nháp chỉ xem được qua link preview.
  • Gọi từ server. RBlog không bật CORS. Mọi request mang key phải đi từ server của frontend (SSR, route handler, server API).
  • Cache ở frontend, làm mới bằng webhook. Frontend cache câu trả lời theo tag; RBlog báo tag nào cần làm mới. Thêm thời gian hết hạn dự phòng (ví dụ 10 phút) cho trường hợp webhook lỗi.

02Bắt đầu

  1. Tạo Content API key. Trong RBlog, vào Tích hợp → Content API (/admin/p/content-api), bấm Tạo khoá, đặt tên (ví dụ "Next production") và chọn thời hạn. Key chỉ hiện một lần: copy ngay. Cần quyền integrations.manage.
  2. Cấu hình webhook. Vào Cài đặt → Tích hợp, nhập URL nhận webhook của frontend (bắt buộc https://) và một secret ngẫu nhiên dài (ví dụ openssl rand -hex 32).
  3. Khai báo URL frontend. Vào Cài đặt → Chung, nhập URL công khai của site. Ở Cài đặt → Tích hợp, kiểm tra đường dẫn preview (mặc định /preview).
  4. Đặt biến môi trường cho frontend như bên dưới, chỉ ở phía server.
.env (frontend)
RBLOG_URL=https://cms.example.com          # APP_URL của RBlog, không có dấu / ở cuối
RBLOG_CONTENT_KEY=rcms_45_xxxxxxxxxxxxxxxx  # Content API key, chỉ dùng phía server
RBLOG_WEBHOOK_SECRET=…                      # giống secret trong Cài đặt → Tích hợp
Không đưa key xuống trình duyệt Ở Next, đừng đặt tên biến bắt đầu bằng NEXT_PUBLIC_. Ở Nuxt, để key trong runtimeConfig gốc, không đặt trong runtimeConfig.public.

03Gọi Content API

Tất cả endpoint nằm dưới /api/v1/content, trả JSON. Id và số 64-bit đi dưới dạng chuỗi; thời điểm là RFC 3339 giờ UTC (2026-10-24T08:00:00Z). Viết một hàm gọi dùng chung, gắn key và tag cache ở một chỗ.

lib/rblog.ts
import "server-only";

const BASE = process.env.RBLOG_URL!;
const KEY = process.env.RBLOG_CONTENT_KEY!;

export class RBlogError extends Error {
  constructor(public status: number, public body: unknown) {
    super(`RBlog ${status}`);
  }
}

/** GET /api/v1/content{path}, cached under `tags`, revalidated at least every 10 minutes. */
export async function rblog<T>(path: string, tags: string[] = []): Promise<T> {
  const res = await fetch(`${BASE}/api/v1/content${path}`, {
    headers: { Authorization: `Bearer ${KEY}`, Accept: "application/json" },
    next: { tags, revalidate: 600 },
  });
  if (!res.ok) throw new RBlogError(res.status, await res.json().catch(() => null));
  return res.json() as Promise<T>;
}
nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    // Server only (NUXT_RBLOG_URL, NUXT_RBLOG_CONTENT_KEY, NUXT_RBLOG_WEBHOOK_SECRET)
    rblogUrl: "",
    rblogContentKey: "",
    rblogWebhookSecret: "",

server/utils/rblog.ts
/** GET /api/v1/content{path} from the Nitro server. */
export function rblog<T>(path: string, query?: Record<string, unknown>) {
  const { rblogUrl, rblogContentKey } = useRuntimeConfig();
  return $fetch<T>(`/api/v1/content${path}`, {
    baseURL: rblogUrl,
    query,
    headers: { Authorization: `Bearer ${rblogContentKey}` },
  });
}
server/api/posts/[slug].get.ts

  (event) => rblog(`/posts/${getRouterParam(event, "slug")}`),
  { name: "rblog", maxAge: 600, getKey: (event) => `post:${getRouterParam(event, "slug")}` },
);

Trang Vue gọi route của chính Nuxt (useFetch('/api/posts/xin-chao')), không gọi thẳng RBlog, nên key không bao giờ ra khỏi server.

Cột cuối là tag nên gắn khi cache câu trả lời, trùng với tag mà webhook gửi về. Tag của bài và trang tĩnh (post:{id}, page:{id}) sẽ có khi phần quản lý bài hoàn thiện; trong lúc đó gắn thêm posts là đủ.

Đường dẫn công khai mà RBlog dùng ở mọi nơi (menu, sitemap, webhook): /posts/{slug}, /{slug} cho trang tĩnh, /categories/{slug}, /tags/{slug}, /authors/{slug}. Nếu route của frontend khác, đổi ở một hàm chuyển đổi duy nhất.

  • html đã được RustCMS escape toàn bộ chữ và chỉ chứa thẻ an toàn, nên chèn thẳng được (dangerouslySetInnerHTML hoặc v-html). Muốn tự render bằng component riêng thì gọi thêm ?include=document để nhận JSON rich text đúng như đã lưu (phiên bản 1 hoặc 2, xem mục 06).
  • outline là danh sách heading của bài theo thứ tự, {level, text, id}, với id trùng id của heading trong html: dùng làm mục lục (mục 06).
  • Slug cũ: API trả 200 {"redirect": "slug-mới"}. Frontend chuyển hướng 301 sang đường dẫn mới để giữ SEO.
  • Trường có thể null: cover, category, seo.og_image, author.slug (tác giả chưa có hồ sơ công khai).
app/posts/[slug]/page.tsx
import { notFound, permanentRedirect } from "next/navigation";
import { rblog, RBlogError } from "@/lib/rblog";

type Heading = { level: 2 | 3 | 4; text: string; id: string };
type Post = { id: string; slug: string; title: string; html: string; outline: Heading[]; /* … */ };
type Answer = Post | { redirect: string };

async function load(slug: string) {
  try {
    return await rblog<Answer>(`/posts/${slug}`, ["posts"]);
  } catch (e) {
    if (e instanceof RBlogError && e.status === 404) notFound();
    throw e;
  }
}

export default async function PostPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = await load(slug);
  if ("redirect" in post) permanentRedirect(`/posts/${post.redirect}`);
  return (
    <article>
      <h1>{post.title}</h1>
      <div className="prose" dangerouslySetInnerHTML={{ __html: post.html }} />
    </article>
  );
}

Bài được cache dưới tag posts, nên mọi sự kiện có tag posts làm mới nó. Muốn làm mới chính xác từng bài theo post:{id}, lưu thêm một bảng ánh xạ slug → id, hoặc chỉ dùng revalidatePath với paths của webhook (mục 10).

06Nội dung rich text

Nội dung bài là document rich text của RustCMS 0.10. Trình soạn thảo ghi phiên bản thấp nhất mà bài cần, nên cả hai phiên bản cùng tồn tại trong dữ liệu và frontend phải xử lý được cả hai:

  • Phiên bản 1: đoạn văn, heading cấp 2 tới 4, danh sách, trích dẫn, khối code, đường kẻ ngang, ảnh (media, alt).
  • Phiên bản 2 là phiên bản 1 cộng thêm bảng, video nhúng (embed), khung ghi chú (callout), chú thích ảnh (caption) và độ rộng ảnh (width). Không node nào của phiên bản 1 đổi nghĩa.
NodeTrong html
Heading<h2 id="gioi-thieu">…</h2> (h2 tới h4)
Ảnh<figure data-width="wide"><img src="…" width="1600" height="900" alt="…"><figcaption>…</figcaption></figure>
Bảng<table><thead>…</thead><tbody>…</tbody></table>, không gộp ô, không độ rộng cột
Embed<figure data-embed="youtube" data-id="dQw4w9WgXcQ"><a href="https://www.youtube.com/watch?v=…" rel="noopener noreferrer">…</a></figure>
Callout<aside class="callout" data-tone="info">…</aside> (info hoặc warn)
  • Ảnh: width, height là kích thước gốc tính bằng pixel, có khi RBlog biết cả hai. data-width là wide hoặc full khi người viết chọn (không có nghĩa là rộng bình thường). Ảnh chưa công khai bị bỏ khỏi html, kể cả ảnh nằm trong callout.
  • Embed: chỉ có youtube và vimeo. data-id đã được RustCMS kiểm tra đúng định dạng của từng nhà cung cấp, nên ghép thẳng vào URL player được. Không có JavaScript thì figure là một link bình thường; frontend thay nó bằng iframe và thêm host của player vào frame-src trong CSP của mình. Trang quản trị không bao giờ tải iframe.
  • Heading id là slug trần của chữ trong heading: bỏ dấu (Đà Nẵng → da-nang), chữ thường, nối bằng -, heading trùng thêm -2, -3. RBlog không thêm tiền tố, để html và outline luôn khớp nhau. Id có thể trùng id của layout (main, comments) hoặc bắt đầu bằng số: đặt id riêng của layout có ký tự slug không bao giờ có (site_main, _comments), mỗi trang chỉ render một bài, và chọn phần tử bằng CSS.escape(id). Muốn anchor có tiền tố (#h-gioi-thieu) thì đổi cùng lúc id của h2–h4 trong html và id trong outline.
  • Tìm kiếm (q) và reading_minutes tính cả chữ trong bảng, callout và chú thích ảnh.

Video, mục lục và ảnh có kích thước

Ví dụ dưới đây đổi figure embed thành iframe, dựng mục lục từ outline, và đặt id của layout theo cách không trùng slug. html đã được escape nên chỉ cần thay chuỗi; không dùng thư viện parse HTML nào phía client.

lib/rich-text.ts
// Embed figures become players. data-embed and data-id are checked by RustCMS
// (youtube: [A-Za-z0-9_-]{11}, vimeo: digits); match them strictly all the same.
const EMBED = /<figure data-embed="(youtube|vimeo)" data-id="([A-Za-z0-9_-]{1,15})">.*?<\/figure>/g;

export function withPlayers(html: string): string {
  return html.replace(EMBED, (_, provider: string, id: string) => {
    const src = provider === "youtube"
      ? `https://www.youtube-nocookie.com/embed/${id}`
      : `https://player.vimeo.com/video/${id}`;
    return `<figure class="embed"><iframe src="${src}" title="${provider} video" loading="lazy"
      allow="encrypted-media; picture-in-picture; fullscreen" allowfullscreen></iframe></figure>`;
  });
}

export type Heading = { level: 2 | 3 | 4; text: string; id: string };

Với <NuxtImg>, render ?include=document bằng component riêng và truyền width, height lấy từ thẻ <img> tương ứng trong html. CSP cho player đặt bằng routeRules hoặc module nuxt-security, với frame-src https://www.youtube-nocookie.com https://player.vimeo.com.

07Danh sách và lọc

Danh sách trả dạng { "data": [...], "meta": { "page", "perPage", "total", "lastPage" } }. Bài và trang xếp theo thời điểm đăng rồi tới id, đều giảm dần, nên các trang không trùng hay sót bài. Mỗi mục trong danh sách có đủ trường như bài đơn lẻ, trừ html, outline và document.

Tham sốÝ nghĩa
page, per_pageTrang từ 1; mặc định 20, tối đa 100. Nên lấy posts_per_page từ /settings
category, tag, authorSlug; kết hợp được với nhau. Slug không tồn tại trả danh sách rỗng
featuredtrue/false (hoặc 1/0)
qTìm không phân biệt dấu và hoa thường trong tiêu đề, tóm tắt, nội dung: viet ra "Việt". Tối đa 100 ký tự
Ví dụ
curl -H "Authorization: Bearer $RBLOG_CONTENT_KEY" \
  "$RBLOG_URL/api/v1/content/posts?category=du-lich&tag=ha-noi&page=2&per_page=10"

Mỗi tham số chỉ được truyền một lần; truyền hai lần sẽ nhận 422 trên tham số đó.

08Ảnh

  • URL ảnh trong html, cover, avatar là URL tuyệt đối trên domain của RBlog: /api/v1/media/{id}/{tên-file}. Không cần key.
  • Chỉ ảnh thuộc nội dung đang công khai mới tải được. Ảnh của bản nháp hay ảnh đã xoá trả 404, nên khi gỡ đăng một bài, ảnh của nó cũng ngừng hiển thị (tối đa 1 giờ do cache).
  • Header Cache-Control: public, max-age=3600. Giới hạn 600 request mỗi phút cho mỗi IP: khi chạy thật, đặt CDN trước RBlog hoặc dùng bộ tối ưu ảnh của framework.
  • RBlog không resize ảnh. Dùng next/image hoặc @nuxt/image; cover.width và cover.height có sẵn để tránh giật layout. Ảnh trong html cũng có width và height trên thẻ <img> (mục 06).

import type { NextConfig } from "next";

const config: NextConfig = {
  images: {
    remotePatterns: [{ protocol: "https", hostname: "cms.example.com", pathname: "/api/v1/media/**" }],
  },
};
export default config;

10Webhook làm mới cache

Mỗi thay đổi ảnh hưởng tới trang công khai (lưu, đăng, gỡ đăng, xoá bài; sửa chuyên mục, thẻ, tác giả, menu, cài đặt), RBlog gửi một POST tới URL webhook. Một sự kiện được gửi ít nhất một lần, có thể tới trễ hoặc lệch thứ tự.

Body webhook
{
  "id": "0192b0a4-7c1e-7000-8000-000000000001",
  "kind": "category.updated",
  "subject": { "type": "category", "id": "12" },
  "tags": ["category:du-lich", "category:du-lich-cu", "posts", "sitemap"],
  "paths": { "old": ["/categories/du-lich-cu"], "new": ["/categories/du-lich"] },
  "created_at": "2026-10-24T08:15:30.123456Z"
}

Receiver phải làm gì

  1. Đọc body thô (bytes), chưa parse JSON.
  2. Kiểm tra chữ ký: X-RBlog-Signature = HMAC-SHA256 hex chữ thường của timestamp + "." + event_id + "." + body, so sánh thời gian hằng (constant time).
  3. Từ chối X-RBlog-Timestamp lệch quá 5 phút so với giờ hiện tại (chống gửi lại).
  4. Bỏ qua X-RBlog-Event-Id đã xử lý (lưu vài giờ trong Redis/KV là đủ).
  5. Làm mới mọi tags và mọi đường dẫn trong paths.old và paths.new. Gặp kind lạ cũng vẫn làm mới.
  6. Trả 2xx trong 10 giây. Lỗi 408, 425, 429, 5xx, timeout được gửi lại (8 lần trong khoảng 1 giờ); 3xx và 4xx khác bị coi là lỗi vĩnh viễn. Redirect không được đi theo.
app/api/rblog-webhook/route.ts
import { createHmac, timingSafeEqual } from "node:crypto";
import { revalidatePath, revalidateTag } from "next/cache";

export const runtime = "nodejs";
const SECRET = process.env.RBLOG_WEBHOOK_SECRET!;
const seen = new Set<string>(); // one instance only: use Redis/KV with a TTL when you run several

export async function POST(req: Request) {
  const id = req.headers.get("x-rblog-event-id") ?? "";
  const ts = req.headers.get("x-rblog-timestamp") ?? "";
  const sig = req.headers.get("x-rblog-signature") ?? "";
  const body = Buffer.from(await req.arrayBuffer());

  const expected = createHmac("sha256", SECRET).update(`${ts}.${id}.`).update(body).digest();
  const given = Buffer.from(sig, "hex");
  if (given.length !== expected.length || !timingSafeEqual(given, expected)) {
    return new Response("bad signature", { status: 401 });
  }
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) return new Response("stale", { status: 401 });
  if (seen.has(id)) return new Response(null, { status: 204 });

  const event = JSON.parse(body.toString("utf8")) as { tags: string[]; paths: { old: string[]; new: string[] } };
  for (const tag of event.tags) revalidateTag(tag);
  for (const path of [...event.paths.old, ...event.paths.new]) revalidatePath(path);
  seen.add(id);
  return new Response(null, { status: 204 });
}
server/api/rblog-webhook.post.ts
import { createHmac, timingSafeEqual } from "node:crypto";

const seen = new Set<string>(); // one instance only: use useStorage("redis") with a TTL when you run several

export default defineEventHandler(async (event) => {
  const { rblogWebhookSecret } = useRuntimeConfig();
  const id = getHeader(event, "x-rblog-event-id") ?? "";
  const ts = getHeader(event, "x-rblog-timestamp") ?? "";
  const sig = getHeader(event, "x-rblog-signature") ?? "";
  const body = (await readRawBody(event, false)) ?? Buffer.alloc(0);

  const expected = createHmac("sha256", rblogWebhookSecret).update(`${ts}.${id}.`).update(body).digest();
  const given = Buffer.from(sig, "hex");
  if (given.length !== expected.length || !timingSafeEqual(given, expected)) {
    throw createError({ statusCode: 401, statusMessage: "bad signature" });
  }
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) throw createError({ statusCode: 401 });
  if (seen.has(id)) return null;

  // Simplest correct invalidation: drop every cached RBlog answer (section 03 caches under "rblog").
  const cache = useStorage("cache");
  for (const key of await cache.getKeys("nitro:handlers:rblog")) await cache.removeItem(key);
  seen.add(id);
  setResponseStatus(event, 204);
  return null;
});

Với route dùng routeRules kiểu ISR/SWR, xoá thêm cache trang theo paths (cách xoá tuỳ nền tảng deploy: Vercel, Netlify, Nitro storage).

Thử ở máy dev Đặt allow_insecure_local = true trong config/webhook.toml của RBlog (chỉ môi trường dev; RBlog từ chối khởi động với cờ này ở production) để nhận webhook http://localhost:3000/api/rblog-webhook. Trạng thái từng lần gửi xem ở trang Queue của admin.
Khi chưa có URL webhook RBlog đánh dấu sự kiện là đã xử lý mà không gửi. Đặt URL sau đó sẽ không gửi lại các sự kiện cũ, nên hãy làm mới toàn bộ cache một lần khi mới cấu hình.

11Xem trước bản nháp

Người viết bấm Xem trước trong admin; RBlog tạo link {frontend_url}{preview_path}?token=… (ví dụ https://blog.example.com/preview?token=…). Token sống 1 giờ, thu hồi được, và chỉ mở đúng một bài.

  • Route preview của frontend gọi GET {RBLOG_URL}/api/v1/preview?token=… từ server, không gửi key.
  • Câu trả lời là bài hoặc trang như bình thường, thêm "preview": {"type": "post" | "page", "status": "draft" | "pending" | "scheduled" | "published"}. published_at có thể là null.
  • Ảnh trong bản xem trước có URL /api/v1/preview/media/{id}?token=…: không cache, không đưa qua bộ tối ưu ảnh dùng chung.
  • Không bao giờ cache trang preview. Đặt noindex. Token hết hạn hoặc sai: hiện thông báo "Link xem trước đã hết hạn".
app/preview/page.tsx
export const dynamic = "force-dynamic";
export const metadata = { robots: { index: false, follow: false } };

export default async function Preview({ searchParams }: { searchParams: Promise<{ token?: string }> }) {
  const { token } = await searchParams;
  if (!token) return <p>Thiếu token xem trước.</p>;
  const res = await fetch(`${process.env.RBLOG_URL}/api/v1/preview?token=${encodeURIComponent(token)}`, {
    cache: "no-store",
  });
  if (res.status === 404) return <p>Link xem trước đã hết hạn hoặc không hợp lệ.</p>;
  if (!res.ok) throw new Error(`RBlog preview ${res.status}`);
  const post = await res.json();
  return (
    <article>
      <p className="badge">Bản xem trước · {post.preview.status}</p>
      <h1>{post.title}</h1>
      <div className="prose" dangerouslySetInnerHTML={{ __html: post.html }} />
    </article>
  );
}

12Sitemap và SEO

GET /sitemap?type=post|page|category|tag&after=<cursor> trả { "data": [{ "type", "path", "lastmod" }], "next": "<cursor>" | null }, tối đa 1000 dòng mỗi lần. Gọi lặp với after = next tới khi next là null. Chuyên mục và thẻ chỉ có mặt khi có ít nhất một bài đã đăng.

app/sitemap.ts (Next.js)
import type { MetadataRoute } from "next";
import { rblog } from "@/lib/rblog";

type Batch = { data: { path: string; lastmod: string }[]; next: string | null };
const SITE = "https://blog.example.com";

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const entries: MetadataRoute.Sitemap = [];
  for (const type of ["post", "page", "category", "tag"]) {
    let after: string | null = null;
    do {
      const query = after ? `&after=${encodeURIComponent(after)}` : "";
      const batch: Batch = await rblog<Batch>(`/sitemap?type=${type}${query}`, ["sitemap"]);
      for (const row of batch.data) entries.push({ url: SITE + row.path, lastModified: row.lastmod });
      after = batch.next;
    } while (after);
  }
  return entries;
}
  • Title và description: ưu tiên seo.meta_title/seo.meta_description của bài, rồi tới title/excerpt, cuối cùng là giá trị mặc định trong /settings.
  • Ảnh chia sẻ: seo.og_image → cover.url → settings.seo.og_image_url.
  • Canonical: seo.canonical_url nếu có, nếu không thì URL của chính trang.
  • Trên 50.000 URL thì chia thành nhiều sitemap kèm sitemap index.

14Checklist trước khi chạy thật

  • Key chỉ nằm trong biến môi trường phía server, không có trong bundle trình duyệt.
  • Mỗi môi trường (staging, production) dùng một key riêng, có thời hạn; thu hồi key cũ khi đổi.
  • Webhook dùng https, kiểm tra chữ ký trên body thô, chặn timestamp cũ, chống trùng theo event id.
  • Cache có thời hạn dự phòng (ví dụ 10 phút) phòng khi webhook lỗi.
  • Slug cũ được chuyển hướng 301.
  • Route preview không cache, có noindex.
  • Có CDN hoặc bộ tối ưu ảnh trước /api/v1/media.
  • URL frontend và đường dẫn preview đã nhập trong Cài đặt của RBlog.
  • Đã làm mới toàn bộ cache một lần sau khi cấu hình webhook.
